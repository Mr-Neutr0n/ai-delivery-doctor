# Schema and Compatibility Policy

AI Delivery Doctor has two public machine-readable contracts:

- `aidoc-v1` — input delivery contract;
- `aidoc-evidence-v1` — output evidence bundle.

Their JSON Schemas live under `schema/`.

## Why schema versions are separate from package versions

The Python package can evolve without forcing every contract/evidence consumer to rewrite.

For example:

- package `0.1.1` and `0.4.0` may both read `aidoc-v1`;
- evidence generated by a newer package can still use `aidoc-evidence-v1` while adding behavior that remains compatible with that schema.

Every evidence bundle includes `toolVersion` so a stored artifact remains traceable to the implementation that produced it.

## Compatibility rule

Within a schema version:

- required field meanings should not change silently;
- status semantics (PASS/WARN/FAIL) remain stable;
- first-blocker ordering remains based on contract order;
- incompatible structural changes require a new schema identifier.

## Before v1.0

The project is still Alpha. We may improve details, but schema-breaking changes should still be explicit and documented rather than hidden behind a package upgrade.

## Evidence consumers

External tools should:

1. check `schema`;
2. record `toolVersion`;
3. tolerate different check types;
4. interpret PASS narrowly;
5. avoid inferring root cause from `firstBlockingCheck` alone.
