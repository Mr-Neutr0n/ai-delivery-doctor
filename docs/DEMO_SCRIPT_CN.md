# 3 分钟路演脚本

## 0:00–0:30｜不要先讲技术栈

开场：

> 很多 AI 项目最危险的一句话不是“报错了”，而是“我这里能跑，应该可以交付”。

> 我做 AI 真实交付以后发现，模型只是前半段。后面还有环境、模型、工具、数据、工作流、部署和用户结果。任何一段没被证明，Demo 能跑都不等于交付完成。

## 0:30–1:20｜直接跑失败场景

```bash
python scripts/showcase.py
```

先指给评委看：

```text
FAIL
FIRST BLOCKER  handoff-receipt
```

强调：

> 它没有给我一个 82 分的“生产就绪度”，它告诉我当前第一处无法证明成立的必要环节在哪里。

## 1:20–2:00｜展示修复后的证据变化

同一个演示继续自动产生：

```text
PASS
IMPROVED
```

说明：

> 我们不是让 AI 自己说“修好了”，而是重新跑同一份验收契约，用新的 evidence 证明条件已经变化。

## 2:00–2:35｜展示 Skill

打开：

```text
.agents/skills/ai-delivery-doctor/SKILL.md
```

说明：

> Skill 负责让 Agent 理解用户目标、设计验收链。真正检查交给确定性程序。AI 负责理解，程序负责证明。

## 2:35–3:00｜落到真实来源与未来

打开 EdgeSafe Vision。

> 这套方法不是为了比赛凭空想出来的。我先在真实边缘 AI 项目里反复遇到“上游看起来正常，下游用户结果没发生”，才把它抽象成通用工具。

收尾：

> AI 越自动化，人越不能靠感觉验收自动化。AI Delivery Doctor 要做的是 AI 时代的交付证据层。
